# SPEC.md: Sensor Trust Intelligence Specification

> Frozen specification record derived from PROGRESS.md (v1.1) and finalized engineering choices.
> Project: VIT Code Apex 3.0, Track 4 (UST), Problem Statement 3: AI-Based Sensor Trust, Drift and False-Alarm Detection.
> Date: 2026-10-10.

## 1. Project Overview & Core Principle
Sensor Trust Intelligence is a software-only intelligence system for multi-sensor streams (v1: temperature) governed by the **"Trust Before Alarm"** principle: an abnormal reading is not automatically an alarm. The system evaluates whether the sensor is trustworthy, identifies active fault modes, verifies if an environmental event is occurring, and makes calibrated decisions to suppress false alarms or escalate genuine emergencies.

## 2. Architecture & Data Layers
### 2.1 Pipeline Flow
```
Sources: Official dataset (if released) | Generator A (dev) | Generator B (robustness only)
   -> Data adapter -> common raw schema
   -> Causal windows -> Feature engine
   -> Sensor-level table (Heads A, B) | Group-level table (Head C)
   -> Head A: untrusted?   Head B: which faults? (7 binary models)   Head C: genuine event?
   -> Provable rules (exact frozen, obvious dropout) + ML scores
   -> Probability calibration
   -> Trust engine (smoothed score, status, recommended action)
   -> Trust-aware alarm layer (real / real + sensor flagged / suppressed / unverified)
   -> Explanations (top 3 reasons, plain sentences)
   -> API + Dashboard (live fault injection, reveal truth, evidence tab)
```

### 2.2 Four Data Layers
1. **Layer 1: Observable Data:** Raw sensor readings (`scenario_id, group_id, sensor_id, variable_type, timestamp, value`). Only layer visible to feature extraction and models.
2. **Layer 2: Derived Features:** Causal windows, own-signal temporal, statistical, data quality, cross-sensor, and group aggregates.
3. **Layer 3: Ground Truth:** Separately stored answer key (`true_value, sensor_untrusted, f_*, fault_severity, true_health, genuine_event, event_*`). Strictly hidden from models; used solely by evaluation code.
4. **Layer 4: Predictions & Decisions:** Calibrated probabilities, trust score, operational status, alarm actions, explanations.

## 3. Non-Negotiable ML Rules
- Model pipeline reads exclusively Layer 1 (raw observable readings). Ground truth stored in separate files.
- Strictly causal: features at time $t$ use readings at or before $t$. Future data is prohibited.
- No `scenario_id`, `sensor_id`, `group_id`, `variable_type`, `timestamp`, or raw `value` as model features in v1.
- Splitting is performed strictly by whole scenarios stratified by difficulty and fault type.
- Fixed random seeds; test set evaluated strictly once at the end.
- Group cross-sensor references exclude the target sensor being evaluated.
- Every run carries run id, seed, config hash, and timestamp.
- Core ML model is LightGBM; SMOTE is prohibited.

## 4. Finalized P0 Engineering Choices & Operational Definitions
1. **Decision 1 — Random Affine Offset (Appendix A.2):** Range $[-10.0, 10.0]^\circ\text{C}$, Uniform distribution. Explicitly classified as an engineering assumption (ENG), not an official problem-statement parameter.
2. **Decision 2 — "Small Group" (Appendix A.6, HARD Tier):** Operationalized as exactly 4 sensors ($n=4$, lower bound of Appendix A.1 integer 4 to 8 sensors).
3. **Decision 3 — "No Clear Majority" (Appendix A.6, HARD Tier):** Operationalized as occurring when no cluster of valid sensor readings contains more than 50% of the sensors; an exact 50/50 split in an even-sized group qualifies.
4. **Decision 4 — "Sensor Near Bounds" (Appendix A.6, HARD Tier):** Operationalized as occurring when the relevant pre-clipping environment or sensor reading is within $\max(3\sigma_k, 2.0^\circ\text{C})$ of its corresponding clipping boundary ($-5.0^\circ\text{C}$ or $50.0^\circ\text{C}$ for environment; $-10.0^\circ\text{C}$ or $60.0^\circ\text{C}$ for sensor). This check is evaluated in canonical Celsius units before unit scaling (Fahrenheit or random affine).
5. **Decision 5 — Sustained Environmental Events (Appendix A.3):** Interpreted as holding at elevated level until scenario end ($t=1920$) after specified rise (5 to 20 min).
6. **Decision 6 — Ground-Truth `sensor_untrusted` Label (Appendix A.4, A.7):** Defined by active fault intervals, including explicit spike window (spike samples + 4 steps) and slow degradation threshold ($d \ge 0.15$).
7. **Decision 7 — Trust Status Exact Boundaries (Appendix A.11):**
   - HEALTHY: $T > 0.8$
   - WATCH: $0.5 \le T \le 0.8$
   - UNRELIABLE: $T < 0.5$
8. **Decision 8 — Simultaneous Fault Cap (Appendix A.1 vs A.5):** Formula $\max(1, \lfloor 0.4 \times n \rfloor)$ acts strictly as an upper bound cap on simultaneous faults; preserves 15% zero-fault healthy scenarios.
9. **Decision 9 — Shared-Cause Severity Similarity (Appendix A.5):** Defined as within $\pm 20\%$ relative tolerance on normalized fault severity ($|s_1 - s_2| / \max(s_1, s_2) \le 0.20$).
10. **Decision 10 — Subtle Faults (Appendix A.4, A.6):** Defined strictly from ranges specified in the source (subtle gain error $g \in [0.90, 0.95] \cup [1.05, 1.10]$).
11. **Decision 11 — Test Set Stride Split (Appendix A.1):** 150 test scenarios at full resolution (stride 1); remaining 150 test scenarios at stride 5 (matching train/val).
12. **Decision 12 — Daily Cycle Phase Interval (Appendix A.2):** Range $[0, 2\pi)$ radians ($[0.0, 6.283185307179586]$), Uniform distribution. Documented as the implementation interpretation of "random phase" in Appendix A.2, not as a numerical range explicitly stated by the original specification.
13. **Decision 13 — Slow Random Wander AR(1) Discretization (Appendix A.2):** Discrete Ornstein-Uhlenbeck AR(1) process with decay factor $\alpha = \exp(-\Delta t / \tau)$ and innovation standard deviation $\sigma_{\text{innov}} = \sigma \sqrt{1 - \alpha^2}$, initialized in the stationary distribution with $(M - 1)$ pre-steps to ensure the 5-step moving average is fully defined from step 0.
14. **Decision 14 — Healthy Missing-Data Distribution (Appendix A.1, Approved Engineering Choice & Correction):** Target population proportion 20% zero missing rate. Since groups contain 4–8 sensors (where exact 20% integer partition is mathematically impossible within every group), each sensor independently receives a zero missing-data rate with probability 0.20 via a seeded Bernoulli trial. For each remaining sensor, its missing-data rate is sampled independently from $\text{Uniform}[0.0, 0.01]$ ($0\%\text{--}1\%$) and kept fixed for that sensor for the scenario. Missing bursts may last up to the configured maximum of 3 consecutive readings. Missing readings are represented as `NaN` (never substituted with zero).
15. **Decision 15 — Healthy Missing-Burst Placement (Appendix A.1, Implementation Choice):** Target missing readings $M = \text{round}(r \times T)$ are partitioned into burst lengths $L \sim \text{DiscreteUniform}[1, \text{burst\_max}]$ ($\text{burst\_max}=3$) and placed at non-adjacent starting positions (buffered by at least 1 valid reading). This guarantees that bursts never merge and consecutive missing readings strictly never exceed 3.
16. **Decision 16 — Mildly Correlated Sensor Noise Factor Model (Appendix A.2, Implementation Choice):** For the 20% of sensors designated as correlated in a group, Gaussian measurement noise is generated via a 1-factor model $\eta_{k, t} = \sigma_k (\sqrt{\rho_k} \xi_t + \sqrt{1 - \rho_k} z_{k, t})$ where $\xi_t \sim \mathcal{N}(0, 1)$ is group-shared noise and $z_{k, t} \sim \mathcal{N}(0, 1)$ is idiosyncratic noise. This strictly preserves each sensor's marginal variance $\sigma_k^2$ and produces pairwise correlation $\sqrt{\rho_j \rho_k} \in [0.2, 0.5]$ without requiring external covariance solvers.
17. **Decision 17 — First-Order Response Lag Discretization (Appendix A.2, Implementation Choice):** Discretized continuous-time physical lag $\tau \frac{dy}{dt} + y = u$ with time step $\Delta t = 1.0$ min via exponential smoothing parameter $\beta = \exp(-\Delta t / \tau)$ for $\tau > 0$ ($\beta = 0$ for $\tau = 0$), initialized in thermal equilibrium $y[0] = u[0]$ to eliminate artificial startup transient at step 0.
18. **Decision 18 — Event Start Time Distribution and Overlap (Appendix A.3, Approved Engineering Choice):** Event start times are sampled uniformly within the scored window from step 480 through step 1919 inclusive (the first 480 steps remain strictly free of genuine environmental events). Start times for multiple events are sampled independently and their physical contributions add additively. Configured via `genuine_events.start_step_min: 480` and `genuine_events.start_step_max: 1919`.
19. **Decision 19 — Asymmetric Ramp Event Durations (Appendix A.3, Implementation Choice):** Ramp rise, hold, and fall durations are drawn independently from $\text{Uniform}[20, 180]$, $\text{Uniform}[30, 180]$, and $\text{Uniform}[20, 180]$ minutes respectively, supporting asymmetric ramp profiles.
20. **Decision 20 — Step with Exponential Recovery Waveform (Appendix A.3, Implementation Choice):** Modeled at sensor $k$ with arrival time $t_{\text{arr}, k} = t_{\text{start}} + d_k$ as $\Delta T_k(t) = A_k \cdot M \cdot \exp(-(t - t_{\text{arr}, k}) / \tau)$ for $t \ge t_{\text{arr}, k}$ with recovery time constant $\tau \in [10, 120]$ min, and 0 for $t < t_{\text{arr}, k}$.
21. **Decision 21 — Pulse Event Waveform (Appendix A.3, Implementation Choice):** Modeled at sensor $k$ with arrival time $t_{\text{arr}, k} = t_{\text{start}} + d_k$ as $\Delta T_k(t) = A_k \cdot M$ for $t_{\text{arr}, k} \le t < t_{\text{arr}, k} + t_{\text{pulse}}$ with pulse duration $t_{\text{pulse}} \in [5, 30]$ min, and 0 elsewhere.
22. **Decision 22 — Stepped Drift Discrete Steps (Appendix A.4, Approved Engineering Choice):** Step count $K$ sampled uniformly from discrete set $\{3, 4, 5\}$, configured via `stepped_steps_min: 3` and `stepped_steps_max: 5` in `config/generator_a.yaml`. Each step moves bias to the next evenly spaced fraction of final bias, reaching full target bias at the end of the ramp.
23. **Decision 23 — Saturating Drift Trajectory (Appendix A.4, Implementation Choice):** Modeled as parameter-free quadratic curve $\text{bias}(u) = B \cdot [1 - (1 - u)^2]$ for normalized ramp progress $u = (t - t_{\text{start}}) / T_{\text{ramp}} \in [0, 1]$.
24. **Decision 24 — Spike Sequence Renewal Process & Labels (Appendix A.4, Implementation Choice):** Inter-spike intervals sampled independently from $\text{DiscreteUniform}[10, 60]$ steps with the first spike starting at $t_{\text{start}}$. Each spike independently samples amplitude in $[3, 40]\sigma_k$, sign ($\pm$), and duration in $\{1, 2, 3\}$ samples. Active label window on spike samples plus following 4 steps combined via boolean OR.
25. **Decision 25 — Frozen Sensor Starting at Step 0 (Appendix A.4, Implementation Choice):** When fault starts at step 0 ($t_{\text{start}} = 0$), the initial healthy equilibrium reading at step 0 is used as base reference. Held for 80% last-reading mode, or offset by randomly signed $[5, 20]\sigma_k$ for 20% wrong-value mode.
26. **Decision 26 — Slow Degradation Interaction Dynamics (Appendix A.4, Implementation Choice):** Noise standard deviation dynamically scaled as $\sigma_k(t) = \sigma_k (1 + 5d(t))$ preserving the 1-factor correlated noise model; degradation bias sign sampled once at onset as $\pm 8\sigma_k \cdot d(t)$; extra missingness sampled independently per step with probability $0.15 d(t)$. Labeled strictly as $f_{\text{slow\_degradation}}$ only; untrusted once $d(t) \ge 0.15$.
27. **Decision 27 — Sensor Transduction Pipeline 11-Step Order (Appendix A.4, Implementation Choice):** Strict execution order: (1) True environment with genuine events & clipping, (2) Response lag, (3) Static offset, (4) Gain error relative to true physical onset temperature $x_{\text{ref}}$, (5) Additive fault biases (drift, spike, degradation bias), (6) Measurement noise scaled by high-noise and degradation multipliers, (7) Frozen-sensor override with jitter, (8) Sensor clipping $[-10, 60]^\circ\text{C}$, (9) ADC quantisation, (10) Union of missing data masks, (11) Unit scaling applied strictly LAST.
28. **Decision 28 — Fault Start Timing & Truncation (Appendix A.4, Implementation Choice):** For the 90% of fault episodes beginning after warm-up, base start step sampled uniformly from $[480, 1919]$ inclusive; 10% present from step 0. Episodes extending beyond step 1920 truncated at scenario end without resampling duration.
29. **Decision 29 — Faulty Sensor Candidate Count, Caps, and Allocation (Appendix A.5, Approved Engineering Choice):** $k_{\text{candidate}}$ sampled once per scenario from $\{0: 0.15, 1: 0.40, 2: 0.25, 3: 0.20\}$ (category "3 or more" represented conservatively by count 3). Both caps enforced: $\text{cap}_{\text{scenario}} = \max(1, \lfloor 0.4 N \rfloor)$, $\text{cap}_g = \max(1, \lfloor 0.4 n_g \rfloor)$. Actual count: $k_{\text{actual}} = \min(k_{\text{candidate}}, \text{cap}_{\text{scenario}}, \sum_g \text{cap}_g)$. When $k_{\text{candidate}} = 0 \implies k_{\text{actual}} = 0$ (preserving 15% zero-fault category). Allocation: uniform draw at each step from currently eligible sensor pool ($c_g < \text{cap}_g$).
30. **Decision 30 — Mechanical Derivation of Valid Triplets (Appendix A.5, Approved Engineering Choice):** A pair is valid iff in `allowed_pairs` and not in `forbidden_pairs`. Valid triplets are derived mechanically as 3-cliques in the valid pair graph. Exactly 11 valid triplets exist (10 in the 5-clique $\{spike, offset\_drift, gain\_error, high\_noise, dropout\}$, plus $\{spike, gain\_error, slow\_degradation\}$). Ordinary 3-fault sensors sample uniformly from all 11 ($P=1/11$).
31. **Decision 31 — Episode Start Timing Regimes & Staggered Windows (Appendix A.5, Approved Engineering Choice):** First episode: 10% step 0, 35% event branch (uniform over active event steps $\mathcal{E}$ in $[480, 1919]$; fallback to $[480, 1919]$ if empty), 55% standard branch (uniform over $[480, 1919]$). Subsequent episode $i \ge 2$: stagger window $W_{\text{stagger}} = [\max(0, t_{\text{start}, i-1} - 100), \min(1919, t_{\text{end}, i-1})]$ with post-warmup intersection $\mathcal{W}_{\text{post}} = W_{\text{stagger}} \cap [480, 1919]$. Case A ($\mathcal{W}_{\text{post}} = \emptyset$): $t=0$ deterministically. Case B ($0 \notin W_{\text{stagger}}$): check event overlap $\mathcal{C}_{\text{event}} = \mathcal{W}_{\text{post}} \cap \mathcal{E}$; with $35/90$ sample $\mathcal{C}_{\text{event}}$ (if non-empty), with $55/90$ sample $\mathcal{W}_{\text{post}}$ (or 100% fallback). Case C ($0 \in W_{\text{stagger}}$ and $\mathcal{W}_{\text{post}} \neq \emptyset$): nominal weights apply (10% step 0, 35% event branch, 55% standard branch).
32. **Decision 32 — Genuine Event Ground Truth Alignment (Appendix A.3, A.5, Approved Engineering Choice):** Active event intervals $\mathcal{E}$ are defined consistently with genuine-event ground truth: the union of time steps $[t_{\text{start}}, t_{\text{end}}]$ across all genuine events in the scenario intersected with $[480, 1919]$.
33. **Decision 33 — Shared-Cause Pair Eligibility, Pre-Allocation, and Parameter Coupling (Appendix A.5, Approved Engineering Choice):** Conditional probability $P(\text{shared-cause} \mid k_{\text{actual}} \ge 2 \text{ and } \exists g \text{ with } \text{cap}_g \ge 2) = 0.15$. Host group $g^*$ selected uniformly from groups with $\text{cap}_g \ge 2$. Two distinct sensors $S_A, S_B$ pre-allocated from group $g^*$ with $c_{g^*} = 2$. Episode 1 is the shared fault on both sensors. If $\max(m_A, m_B) == 3$, shared type sampled uniformly from 6 triplet-capable types; else from all 7. Conditional triplet distribution: when $m_k=3$, sample uniformly from triplets containing the shared type. Start offset: if $t_A = 0 \implies \delta = 0$ ($t_B = 0$); if $t_A \in [480, 1919] \implies \delta \in [\max(-10, 480 - t_A), \min(10, 1919 - t_A)]$, preserving event overlap if $t_A \in \mathcal{E}$. Parameter coupling within $\le 20\%$ relative tolerance: spike size in sigma & sign identical; offset drift multiplier in sigma, sign, shape, and stepped $K$ identical; gain deviation $|g-1|$ and direction relative to 1 identical; frozen value & jitter mode identical; high noise multiplier & bursty mode identical; dropout $p_{\text{enter}}$ and uncapped mean gap $\mu_{\text{uncapped}}$ coupled within 20% (effective capped expectation $E[\min(X, 100)] = \mu [1 - (1 - 1/\mu)^{100}]$ satisfies theoretical severity tolerance $\le 12\% \le 20\%$); slow degradation final damage $d_{\text{final}} \in [0.3, 0.9]$ & sign identical.
34. **Decision 34 — Ground-Truth Aggregation & Observable Isolation (Appendix A.5, A.7, Approved Engineering Choice):** When no faults active: `fault_severity` = 0.0, `true_health` = 1.0, `sensor_untrusted` = 0, $f_{\text{type}} = 0$. Concurrent active faults: `fault_severity` = max active severity, `true_health` = 1 - max active severity, `sensor_untrusted` = logical OR of active untrusted flags. Slow degradation labeled $f_{\text{slow\_degradation}} = 1$ throughout episode, but `sensor_untrusted` = 1 only when damage $d(t) \ge 0.15$. Layer 1 observable table contains strictly the 6 standard columns (`scenario_id, group_id, sensor_id, variable_type, timestamp, value`).
